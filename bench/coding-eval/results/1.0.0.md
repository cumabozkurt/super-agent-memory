# Coding eval 1.0.0: results and push-policy recommendation

**Run:** 2026-10-07, SAM `src/` at the v2 base (`abc3b65`), default config.

**Data:** `runs.jsonl` holds 1,899 graded calls. `tables-1.0.0.md` has every table, including per-task results. The
method is in `../README.md`.

**Design**
- **Tasks:** 34 memory-necessary pairs (26 EN, 8 TR) and 10 harm tasks.
- **Arms:** 6, each at temperatures 0 and 0.7.
- **Conditions:**
  - gemini-3.8-flash on the small store (50 rows);
  - gemini-3.8-flash on the large store (270 rows);
  - deepseek-v4-flash on the small store.
- **Push-after-failure:** retried on 109 paired failures.
- **Statistics:** Δ is in percentage points versus no memory, with a paired task-cluster bootstrap 95% CI (10k resamples).

## Push-after-failure: compact fix card on retry

Fix tasks only (10 pair tasks with a realistic failure signature; failures occurred on 8). Every failed first
attempt was retried twice from the same conversation:
- *plain*: the error output only;
- *card*: the error output plus one `<memory fix>` line, found by searching the error text alone. The line is about 50 tokens.

| | n | plain retry pass % | retry + card pass % | Δ [95% CI, task-cluster] | discordant (card-only / plain-only) |
|---|---|---|---|---|---|
| all failures | 109 (8 tasks) | 54.1 | **78.9** | **+19.7 [+4.5, +38.8]** | 29 / 2 |
| card hit the task's own fix | 80 (8 tasks) | 57.5 | 90.0 | — | 27 / 1 |
| card hit another fix (miss) | 29 (7 tasks) | 44.8 | 48.3 | — | 2 / 1 |

- The error-text lookup found the right fix for 73% of the failures that actually occurred. It does better on the
  realistic runtime errors than on assertion-style messages.
- A wrong card did no detectable harm (n = 29).
- The gain is concentrated in three tasks, where the error does not reveal the fix:

  | task | plain | card |
  |---|---|---|
  | `migration-lock` | 7/18 | 16/18 |
  | `dev-api-ipv4` | 0/18 | 12/18 |
  | `date-only-local` | 0/14 | 5/14 |

  On tasks where the error already reveals the fix, both retries pass (`parasut-retry-after` 18 vs 19, `vitest-forks` 20 vs 20).
- The exact McNemar p (< 0.001) treats retries as independent. They are clustered in 8 tasks, so read the bootstrap CI instead.

## Recommendation

**(i) Ship the compact fix card as push-after-failure, gated. Yes.**
- **Evidence:**
  - The card retry beats the plain retry by +19.7 pp, 95% CI [+4.5, +38.8] over 8 tasks.
  - When the card misses, there is no measurable harm.
  - It costs about 50 tokens, and only after a failure.
- **Ship it with these gates:**
  - Fire only after an observed failing command or test.
  - Push one line.
  - Push only a `fix`/`bug` row that is the top hit for the error text and was not already shown this session.
  - Keep the signature as a lookup key only (X9).
- **Not yet proven:**
  - Retrieval from real error output. The error messages and the fix memories here were written by the same author,
    so a 73% hit rate is an optimistic estimate.
  - The acceptance test before default-on is a replay corpus of real failures (P0-2/P0-G).

**(ii) Ship 1-experience push (always push the top-1 fix memory at prompt time)? No.**
- **Evidence:**
  - Pooled, it scores −1.5 pp [−5.9, +2.0] versus SAM, and is non-positive in every condition.
  - On this set the CI rules out a gain larger than about 2 pp.
- **Why it does not help:** when a fix is relevant, SAM's gated recall has usually already shown it. The ungated
  push then adds an *unrelated* fix line: 29 of 31 additions on the small store and 26 of 27 on the large store were
  unrelated. That is about +50 tokens per prompt for nothing.
- **What to do instead:** keep fixes in gated recall and in the push-after-failure card above. Drop the "≤ 1
  experience per push" rule in favour of a session experience budget (X1) that only these two surfaces draw from.

## Other findings that bear on the v2 card and push work

1. **Pull is the biggest lever after memory itself.** Pull adds +21.1 pp [+10.3, +33.3] on top of push. There are two causes:
   - **The card cuts the decisive tail of a line.** With `cardGistMax` = 80, the card shows `Lint aracı artık ESLint
     değil, Biome: CI komutu \`pnpm biome check...` and loses `--error-on-warnings`. Similar losses:

     | task | push only | with pull (`mem_get`) | detail the card cut |
     |---|---|---|---|
     | `lint-update` | 0/6 | 6/6 | `--error-on-warnings` |
     | `tr-date-format` | 1/6 | 5/6 | timezone |
     | `feature-flag` | 2/6 | 5/6 | `ff-` prefix |

     The model recovers the detail only through `mem_get`.
   - **Recall misses.** The task's own memory was neither in the card nor in recall for 8/34 pairs (small store) and
     10/34 (large store). Examples: `valibot`, `ids`, `config-get` and `soft-delete`, a TR/EN paraphrase gap.
     With pull, the model searched and found most of them, but not `config-get` (0/6 in every SAM arm) or `soft-delete` (`sam` 0/6).
   - **Implications:**
     - Keep the MCP tools on.
     - Do not shorten rule and decision lines in a way that cuts commands or flags. Either cut on a clause boundary,
       or raise `cardGistMax` for `convention`/`decision` rows.
     - The redteam X5 concern (pull hurts) is not reproduced here. Pull was the arm that helped.
2. **A full dump ties SAM + pull at these store sizes** (+1.5 [−5.9, +9.3]). It costs 2.0k tokens per session at 50
   rows and 9.8k at 270. On gemini in the large store, the cost per task was $0.0067 for the dump versus $0.0020 for
   SAM. That supports "dump-if-small" (X3) as a P2 option for small stores only. At 270 rows it is already about 25× SAM's
   injected tokens for no gain.
3. **Harm is small and not resolvable with 10 harm tasks.** Harm rates were 1.8–5.3% across arms, and every harm Δ CI
   contains 0. One concrete mechanism was seen: over-applying a card rule. The "API timestamps without ms" rule turned
   a numeric SQL parameter into an ISO string in `h-session-purge`:

   | arm | `h-session-purge` |
   |---|---|
   | sam | 4/6 |
   | dump | 4/6 |
   | samPush | 6/6 |

   Per-prompt recall put near-miss lines on the harm prompts (5 lines across the 10 prompts on the small store, 8 on the
   large store) without measurable damage.
4. **The irrelevant control does not hurt** (+3.9 [−0.5, +9.8]). The cost of SAM is not "extra tokens". It is wrong or
   over-applied lines.
5. **Memory cut reasoning spend.** With no memory, gemini reasoned longer while guessing conventions: $0.0031–0.0039
   per task, versus $0.0009–0.0010 for push only.
6. **Knowledge updates:**
   - SAM's topic supersession retired 2 of 3 stale rows. The third, the old `v2:` cache-key format, was still live and
     surfaced once, in the `cache-key-update` recall.
   - The update tasks passed with pull: `cache-key-update` 6/6, `lint-update` 6/6.
   - With push only, `lint-update` failed (0/6) because of card truncation, not because of the stale row.

## Honest limits

- **The effects are upper bounds by construction.** Tasks point at "our way", and the tests check arbitrary planted
  facts. The models cannot read the repo, so they cannot fall back on code. The comparisons *between* memory arms are
  the decision-relevant numbers, not the +55 to +80 pp versus no memory.
- **Sample size:** n = 34 pair tasks, 10 harm tasks and 8 retry tasks, with 2 cheap models at low reasoning effort.
  The CIs are wide. "No difference" means "no difference larger than the CI", not equivalence. This is especially true
  for harm.
- **One author wrote the tasks, memories, tests and error strings.** No blind set was used.
- **Harness details:**
  - DeepSeek runs used `--max-tokens 16000`. With 8000, it often reasoned past the cap and returned nothing.
  - In 13 DeepSeek replies there was still no code block (irr 7, sam 4, top1 2). These were graded as failures.
  - DeepSeek used 5.2 tool calls per task, and 34 of its 88 `sam` runs needed the forced "answer now" final turn.
  - One DeepSeek run is missing: temperature 0, `sam`, `vat-half-even`. The tool loop exceeded the harness time limit
    on three attempts. That task is averaged over its remaining run.
- **Extra retry runs:** arms none and irr also ran at temperatures 0.35 and 1 on fix tasks, only to collect more
  failures for the retry experiment. They are excluded from the main tables.
